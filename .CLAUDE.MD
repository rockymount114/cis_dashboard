# CIS Dashboard - Claude Code Development Guide

## Project Overview

**CIS Dashboard** is a Next.js utility collection dashboard for visualizing Customer Information System (CIS) data and tracking key performance indicators (KPIs). The application connects to a Microsoft SQL Server database, implements Redis caching, and provides real-time data visualization through interactive charts and animated KPI cards.

## Tech Stack

- **Frontend**: Next.js 15.5.5 with React 19.1.0 and TypeScript
- **Database**: Microsoft SQL Server (MSSQL) with readonly access
- **Caching**: Redis 5.10.0 with 5-minute TTL
- **Styling**: Tailwind CSS 4.x with custom animations
- **Charts**: Recharts 3.2.1 for data visualization
- **Data Fetching**: SWR 2.3.6 for client-side caching
- **Fonts**: Geist font family from Google Fonts

## Key Features & Implementation Details

### Database Layer (`lib/db.ts`)
- **Connection Management**: Pool-based connection with 5-minute timeouts
- **SQL Queries**: Complex CTE-based queries for KPI calculations
- **Tables Accessed**:
  - `ADVANCED.BIF951` - Billing transactions
  - `ADVANCED.BIF956` - Payment transactions
- **Query Filters**: Processed records only, excludes canceled/no-bill/collection bills, readonly access

### Redis Caching (`lib/redis.ts`)
- **TTL**: 60 minutes (3600 seconds) for all cached data
- **Key Patterns**:
  - `kpi_data_{startDate}_{endDate}`
  - `chart_data_{startDate}_{endDate}`
- **Connection**: URL-based with password authentication
- **Utilities**: Cache invalidation and testing functions

### API Endpoints

#### GET `/api/kpis?startDate=&endDate=`
Returns KPI data with optional date filtering
- **Query Parameters**: `startDate` (YYYY-MM-DD), `endDate` (YYYY-MM-DD)
- **Response**: `{ totalCustomers, totalAccounts, totalBilled, totalPayments, totalUnpaid }`
- **Caching**: 5-minute Redis cache with date-range-specific keys

#### GET `/api/kpis/billed-vs-collected?startDate=&endDate=`
Returns monthly billed vs collected chart data
- **Query Parameters**: `startDate`, `endDate` (both required)
- **Response**: Array of `{ month, billed, collected }`
- **Processing**: SQL CTEs with monthly aggregation

### Frontend Components

#### KpiCard Component (`app/components/KpiCard.tsx`)
- Animated number counting using `react-countup`
- Currency formatting with Intl.NumberFormat
- Responsive design with Tailwind CSS

#### BilledVsCollectedChart Component (`app/components/BilledVsCollectedChart.tsx`)
- Line chart using Recharts
- Responsive to container size
- Shows monthly billed vs collected trends

#### Main Dashboard (`app/page.tsx`)
- Date range filtering with debounced inputs (300ms)
- SWR for data fetching with revalidation
- Responsive grid layout

### Performance Optimizations

1. **Redis Caching**: All API responses cached for 5 minutes
2. **Debounced Inputs**: 300ms delay on date filters to prevent excessive API calls
3. **Connection Pooling**: SQL Server connection pooling for efficiency
4. **Memoization**: SWR caching on the client-side
5. **Readonly Database Access**: Prevents accidental data modification

### CSS & Styling

- **Tailwind CSS 4.x** with custom animations
- **Geist Font** family imported via Next.js font optimization
- **Responsive Grid** layout for KPI cards
- **Custom CSS Animations** for loading states and transitions

## Development Guidelines

### When Adding New Features

1. **Database Queries**: Use the existing `withCache` pattern in `lib/db.ts`
2. **API Routes**: Add new routes under `app/api/` following existing patterns
3. **Components**: Place React components in `app/components/`
4. **Caching**: Always implement Redis caching for expensive operations
5. **Type Safety**: Use TypeScript interfaces for all data structures

### Error Handling

- Database errors are thrown and logged
- Redis connection failures fall back to database queries without caching
- Frontend shows fallback values for missing data

### Data Flow

1. User interacts with dashboard (date range changes)
2. Frontend calls API endpoints with SWR
3. API checks Redis cache first
4. If cache miss, queries SQL Server
5. Results cached in Redis and returned
6. Frontend displays data with animations

## Testing & Debugging

### Redis Testing
```bash
# Test Redis connection
node -e "require('./lib/test-cache').testRedisConnection()"

# Clear cache manually
node -e "require('./lib/cache').clearAllCache()"
```

### API Testing
- Use browser developer tools to inspect API calls
- Check Network tab for cache headers and response times
- API responses include console logs for cache hits/misses

### Database Debugging
- SQL queries are logged in error cases
- Connection timeout is 5 minutes for long-running queries
- Use `SET NOCOUNT ON;` at beginning of SQL queries

## Security Considerations

- Database connection uses readonly permissions
- All external inputs are parameterized in SQL queries
- Redis connection credentials are stored in environment variables
- No client-side database connection strings

## Common Issues & Solutions

### Redis Connection Failed
- Check `CACHE_REDIS_URL` in `.env.local`
- Verify Redis server is accessible from deployment environment
- Redis will be bypassed automatically - system continues without caching

### Database Timeouts
- Default timeout is 5 minutes - adjust in `lib/db.ts` if needed
- Check network connectivity to SQL Server
- Verify database credentials and permissions

### Data Not Updating
- Cache TTL is 5 minutes - data will update automatically
- Use cache clearing utilities in `lib/cache.ts` for immediate updates
- Check API endpoints directly in browser for real-time data
